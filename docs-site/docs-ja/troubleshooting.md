# よくある質問

まず「空间设置」（スペース設定）→「容器自检」（コンテナセルフチェック）を試してください。起動、画面、スクリーンショット、独立プロセス、WebView、MCP などの基本機能をカバーし、コピー可能なレポートを生成します。

## インストールと起動

### APK のインポートに失敗する

| メッセージ | 原因 | 対処 |
| --- | --- | --- |
| `SIGNATURE_MISMATCH` | 同じパッケージ名で異なる署名のインストール記録がある | 古いアプリをアンインストールするか、同じ署名で再パッケージする |
| `SECURE_ENV_REQUIRED` | 対象が `REQUIRE_SECURE_ENV` を宣言している | 現在のコンテナはこの要件を満たしていないため、インストールできません |
| `minSdk` 関連のエラー | 対象の minSdk が現在のシステムより高い | システムをアップグレードするか、互換性のあるバージョンに変更する |
| 解析失敗 / 有効な APK ではない | ファイルが破損している、または APK ではない | 再ダウンロードし、ファイルが完全か確認する |

### インストールは成功したが起動に失敗する

- まず `ABI_MISMATCH` が返されていないか確認します。arm64 のネイティブライブラリのみを含むアプリは、x86_64 エミュレーターでは実行できません。
- 対象アプリが加固（パッカー）、ホットアップデート、独自のネイティブ SDK を使用している可能性があります。こうしたアプリは個別に対応する必要があります。
- 「コンテナセルフチェック」を開き、コンテナの基本機能が正常であることを確認します。
- アプリ名、バージョン、エラーメッセージを記録し、issue を提出します。

### 起動後に黒画面、白画面、クラッシュが発生する

よくある原因：

- 対象アプリが依存するネイティブライブラリが読み込まれていない。
- 対象アプリが実行環境の異常を検出した。
- 対象 Activity がまだ仮想化されていないシステム機能を使用している。
- リソースまたは split が不完全。

次のことを試してください。

1. split APK がすべてインポートされているか確認します。
2. 「运行管理」（実行管理）でそのアプリのすべてのプロセスを終了してから、再度起動します。
3. 別のバージョンまたはアーキテクチャの APK で検証します。
4. 「コンテナセルフチェック」のレポートとエラーメッセージを添えて issue を提出します。

### デスクトップにアプリアイコンがない

- 「スペース設定 → アプリ管理」に移動し、「仮想アプリ」リストにそのアプリがあることを確認します。
- アプリが一覧に残っている場合は、アプリリストの「起動」を使うかデスクトップレイアウトを修復します。
- アプリが一覧にない場合は、ホストアプリまたは APK から再インポートします。

### 再起動後にインストール記録が消える

通常、インストール記録は永続化されます。NestSpace のアプリデータを消去した場合、インストール記録とインスタンスデータが一緒に失われるため、再インポートが必要です。

## 複製（マルチインスタンス）とメモリ

### 複数のアプリを同時に開くと、以前のアプリが閉じられる

これは想定されたメモリ管理の動作です。

- コンテナプロセスプールはデフォルトで最大 16 個のスロットを自動管理します。
- メモリが逼迫すると、最も長く使われていないバックグラウンドコンテナが優先的に終了されます。フォアグラウンドのコンテナは終了されません。
- 「スペース設定 → コンテナスロット」で固定の上限を設定できます。
- 「実行管理」で不要なプロセスを手動で終了し、メモリを解放できます。

### インスタンスデータは失われる？

プロセスを終了してもデータは削除されません。アプリデータは `files/vspace/data/<package>/<instance>/` に保存され、次回起動時にも引き続き使用されます。

### インスタンス間でデータを共有できる？

できません。各インスタンスの files、cache、databases、code_cache、SharedPreferences 名前空間は独立しています。データを共有する必要がある場合は、アプリ自体のアカウント同期やエクスポート機能を利用するしかありません。

## バックグラウンド実行とヘッドレス実行

### `LAUNCH_BLOCKED`

NestSpace の画面を開いていない状態でコンテナを起動するには、オーバーレイ権限によるバックグラウンド Activity 起動の例外許可が必要です。

1. 「スペース設定 → MCP 制御サービス」を開きます。
2. 画面の指示に従って「显示在其他应用上层」（他のアプリの上に表示）権限を付与します。
3. `space_launch` を再度呼び出します。

### バックグラウンドに回ったアプリがシステムに終了される

Android はメモリとバックグラウンドポリシーに応じてプロセスを回収します。NestSpace は、フォアグラウンドのコンテナが自身のスロット管理によって閉じられないことを保証できるだけで、システムがアプリ全体を回収することを防ぐことはできません。長期間バックグラウンドで実行する必要がある場合は、バッテリー最適化をオフにし、バックグラウンドでの動作を許可してください。

### スケジュールタスクが実行されない

- タスクが有効になっていることを確認します。
- NestSpace のバックグラウンド実行を許可し、省電力モードによるアラームの制限をオフにします。
- システムが正確なアラーム権限を制限していないか確認します。
- タスクのスケジュールは次回起動後に復元されます。

## AI アシスタント

### アシスタントがモデル未設定と表示する

現在のバージョンにはオフラインのルール Agent はありません。タスクを送る前に使用可能なモデルを設定してください。設定が完了するまで、コマンドやツール呼び出しは実行されません。

- 「スペース設定 → モデル設定」で使用可能な設定が保存され、選択されていることを確認します。
- 「测试连接」（接続テスト）をタップして、インターフェースが使用可能か確認します。
- Base URL、API Key、モデル名を確認します。
- 対話内のエラーメッセージと「トークン統計」を確認します。

### ツール呼び出しの上限に達した

デフォルトでは 1 回の対話で最大 128 回までツールを呼び出せます。複雑なタスクでは「最大ツールラウンド」を増やすか、タスクをいくつかのステップに分割してください。

### アシスタントが対象アプリを操作しない

アシスタントは「仮想スペース 1」に固定されています。アプリがインストールされて起動しており、ほかのインスタンスに占有されていないことを確認してください。

### 音声認識の結果が出ない

- 録音権限を付与します。
- オフライン音声モデルがダウンロード済みであることを確認します。
- 「スペース設定 → フローティングドット」で言語モデルを切り替えてから再試行します。
- 初回ダウンロードに失敗した場合は、別のモデルソースに変更して再試行します。

## ブラウザ

### ページが開かない、または白いまま

- ネットワーク接続を確認します。
- プロキシを有効にしている場合は、プロキシアドレスとポートが正しいことを確認するか、一時的にプロキシをオフにします。
- 一部のサイトは WebView をブロックします。システムブラウザで同じアドレスを開いて確認してみてください。
- ページにログインや認証コードが必要な場合は、「交给用户」（ユーザーに引き継ぐ）モードで処理します。

### プロキシが有効にならない

- Android 10 以降かつ WebView が `PROXY_OVERRIDE` をサポートしている必要があります。
- サーバーアドレスにはホスト名または IP のみを入力し、`http://`、ポート、スラッシュを含めないでください。
- ユーザー名／パスワードが必要なプロキシには対応していません。
- 変更後はブラウザのタブを開き直してください。

### ダウンロードに失敗する

- システムと NestSpace にダウンロードディレクトリへの書き込み権限があることを確認します。
- 空きストレージ容量を確認します。
- 一部のサイトは Blob や保護されたリンクを使用しており、WebView では直接ダウンロードできない場合があります。

## MCP

### 接続が拒否される

- 「MCP 制御サービス」でサービスが実行中と表示されていることを確認します。
- USB モードでは `adb forward tcp:8765 tcp:8765` が実行済みであることを確認します。
- LAN モードでは、同じ Wi-Fi に接続し、IP が正しく、LAN 権限が付与されていることを確認します。

### 401 / 404

- 401：Token が誤っているか、`Authorization: Bearer <token>` が付いていません。
- 404：パスが誤っているか、セッションが期限切れです。アドレスは `/mcp` で終わる必要があります。30 分間アイドル状態が続くとセッションが回収されるため、再接続してください。

### PC から接続できるがスマートフォン側に変化がない

- コンテナツールを呼び出しており、対象アプリが `virtual-1` で起動していることを確認します。
- バックグラウンド起動が必要な場合は、オーバーレイ権限を確認します。
- MCP ツールが返すエラーメッセージを確認します。

## データとリセット

### データの場所

```text
/data/user/0/com.coke.nestspace/files/vspace/
  apps/                     安装的 APK
  data/<package>/<instance>/ 实例数据
```

### 完全にリセットする方法

システム設定で NestSpace のアプリデータを消去するか、システムから NestSpace をアンインストールします。どちらの場合も次のものが削除されます。

- すべての仮想アプリとインスタンスデータ。
- デスクトップのレイアウトと壁紙。
- モデル設定、メモリ、スキル、スケジュールタスク。
- MCP Token。

### 1 つのアプリだけを削除する方法

「スペース設定 → アプリ管理」→ アプリの行の「卸载」（アンインストール）。これにより、そのアプリとそのすべてのインスタンスデータだけが削除されます。

## 問題を報告する際に添付するもの

- スマートフォンの機種、Android バージョン。
- NestSpace のバージョン（「スペース設定 → バージョン情報」）。
- 対象アプリの名前とバージョン。
- 「コンテナセルフチェック」レポート。
- 具体的な操作手順とエラーメッセージ。
