# アプリのインストールと管理

入口：**「空间设置」（スペース設定）→「应用管理」（アプリ管理）**。

![アプリ管理とマルチインスタンス](screenshots/app-manager.jpg)

この画面には 2 つの追加方法があります。

1. **アプリをインポート**：ホスト Android にインストール済みのアプリから APK を選び、仮想空間へインストールします。
2. **APK をインポート**：ローカル APK、または split APK の全ファイルを選びます。

インポートしたアプリはすべて、独立したインスタンスとデータディレクトリを持つ NestSpace の仮想アプリになります。現在の UI は「仮想アプリ」と「デスクトップアプリ」を分けず、システムアプリのショートカットも作成しません。

## ホストにインストール済みのアプリをインポート

1. 「アプリをインポート」をタップします。
2. NestSpace がインポート可能なホストアプリを読み取ります。
3. 1 つ以上のアプリを選択します。
4. 「インポート」をタップします。

- インポートされるのはホストアプリの APK だけで、アカウント、非公開データ、ログイン状態はコピーされません。
- 初回起動時に「インスタンス 1」が作成されます。
- 同じパッケージが既にある場合、上書きする旨が表示されます。
- 上書き時も署名、最低システムバージョン、コンテナ互換性を検証します。
- Gmail などのシステム系アプリもインポートできますが、システムサービスやネイティブライブラリへの依存により実行できない場合があります。

## APK をインポート

1. 「APK をインポート」をタップします。
2. システムのファイル選択画面で APK を選びます。
3. 解析、コピー、インストールの完了を待ちます。

split APK の場合は、すべてのファイルを一度に選択します。

```text
base.apk
split_config.arm64_v8a.apk
split_config.xxhdpi.apk
...
```

base だけを選ぶとコード、ネイティブライブラリ、リソースが不足し、起動に失敗する場合があります。

| 検査 | 失敗時の動作 |
| --- | --- |
| パッケージ名 | インストールを拒否 |
| 署名の一貫性 | 同じパッケージに異なる署名がある場合 `SIGNATURE_MISMATCH` |
| `minSdk` | 現在のシステムより高い場合インストールを拒否 |
| `REQUIRE_SECURE_ENV` | 安全な環境を要求する場合 `SECURE_ENV_REQUIRED` |
| ABI | インストールは成功する場合があるが、起動時に対応ライブラリがなければ `ABI_MISMATCH` |

## 仮想アプリとインスタンス

アプリ行には、アイコン、名前、パッケージ、バージョン、インスタンス、起動、複製、アンインストール、ネイティブライブラリ状態が表示されます。

- インスタンスをタップすると、そのインスタンスを起動します。
- 「起動」は最後に選択したインスタンスを使用します。
- 「複製」は新しい独立インスタンスを作成します。

各インスタンスは `files`、`cache`、`code_cache`、`databases`、`getDir`、SharedPreferences、ネイティブライブラリの展開先を個別に持ち、相互にデータを読み取れません。

### インスタンス詳細

インスタンスをタップすると詳細画面が開き、インスタンス ID、作成日時、最終起動、環境バージョン、互換設定、最終診断、実際のデータディレクトリを確認できます。

「このインスタンスのデータを消去」は対象インスタンスだけをリセットします。同じアプリの他のインスタンスとインストール済み APK は残ります。

### 同時実行数の上限

プロセスプールはデフォルトで自動管理され、最大 16 スロットです。メモリ不足時は最も長く使われていないバックグラウンドコンテナが閉じられ、フォアグラウンドは維持されます。「スペース設定 → アプリとコンテナ → コンテナスロット」で 1〜16 の固定上限を設定できます。

## アンインストール

仮想アプリをアンインストールすると、APK、全インスタンス、インスタンスデータ、キャッシュ、データベース、NestSpace 名前空間の SharedPreferences が削除されます。復元できません。

プラグインと仮想アプリは別のデータ境界を使用します。仮想アプリを削除してもプラグインは残り、プラグインを削除しても仮想アプリは残ります。

## よくあるインストール問題

### `SIGNATURE_MISMATCH`

同じパッケージ名に異なる署名の APK がインストールされています。旧アプリをアンインストールするか、同じ署名で再ビルドしてください。

### `SECURE_ENV_REQUIRED`

対象アプリが要求する安全な実行環境を NestSpace は提供しないため、インストールを拒否します。

### `ABI_MISMATCH`

APK のネイティブ ABI がデバイスまたは選択中の実行環境と一致しません。一致するパッケージを使用してください。ARM64 実機や ARM 変換エミュレーターでは通常 arm64 ホスト APK を使用します。

### 起動後の黒画面またはクラッシュ

加固（パッカー）、ネイティブ SDK、動的ロード、依存関係の競合が原因のことがあります。「スペース設定 → アプリとコンテナ → コンテナ詳細 → コンテナセルフチェック」を実行し、アプリのバージョン、エラー、診断レポートを添えて報告してください。

### インストール成功後にデスクトップアイコンがない

「スペース設定 → アプリ管理」でアプリが残っているか確認し、そこから起動してください。デスクトップレイアウトの破損やリセットでアイコンだけが消える場合があります。
