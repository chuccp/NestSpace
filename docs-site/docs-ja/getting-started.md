# クイックスタート

このページでは、NestSpace のインストールから最初の APK のインポート、起動、複製（マルチインスタンス）までをゼロから順に説明します。手順全体で root もアクセシビリティサービスも不要です。スマートフォン上の操作に PC や adb は必要ありません。

## 1. システムバージョンの確認

- Android 7.0（API 24）以降。
- Android 7.1、15、16、17 で動作確認済みです。
- 対象アプリが arm64 のネイティブライブラリのみを含む場合は arm64 の実機が必要です。x86_64 エミュレーターでは起動前に `ABI_MISMATCH` が返されます。

## 2. NestSpace のインストール

プロジェクトの [Releases](https://github.com/chuccp/NestSpace/releases/latest) から正式ビルド済みの APK（例：`NestSpace-vX.Y.Z-arm64.apk`）をダウンロードするか、[ソースからのビルド](building.md)の手順で自分でパッケージしてから、通常の APK と同じようにインストールします。

初回起動時は NestSpace のデスクトップが表示されます。デスクトップにはデフォルトで次のものが含まれます。

- **「空间设置」（スペース設定）**：すべての設定とアプリへの入口です。
- **「AI助手」（AI アシスタント）**：ローカルの AI アシスタントです。
- **「浏览器」（ブラウザ）**：内蔵のマルチタブブラウザです。
- **「运行管理」（実行管理）**：現在実行中のコンテナプロセスとメモリ使用量を確認できます。

ホスト APK またはローカル APK からインポートした仮想アプリもここに表示されます。
「プラグインセンター」は追加のデスクトップ入口です。独立したアプリとして開き、ソースプラグインとインストール済み `.nest` パッケージを管理します。

![NestSpace デスクトップ](screenshots/desktop.jpg)

## 3. ホストにインストール済みのアプリをインポート（任意）

NestSpace はシステムアプリのショートカットを作らず、ホスト APK の仮想コピーをインストールします。

1. 「スペース設定 → アプリ管理」を開きます。
2. 「アプリをインポート」をタップします。
3. デバイスにインストール済みのアプリを 1 つ以上選択します。
4. 「インポート」をタップして完了を待ちます。

ホストアプリのアカウント、非公開データ、ログイン状態はコピーされません。初回起動時に独立した「インスタンス 1」が作成されます。

## 4. 最初の APK をインポートする

1. まず APK をスマートフォンからアクセスできる場所（例：「下载」（ダウンロード）フォルダ）に置きます。
2. 「スペース設定」→「アプリ管理」→「导入 APK」（APK をインポート）をタップします。
3. システムのファイルピッカーで APK を選択します。
4. インポートが完了するまで待ちます。インストールに成功すると、アプリはデスクトップに自動的に表示され、アプリ管理の「虚拟应用」（仮想アプリ）リストにも表示されます。

アプリが split 形式（1 つの base APK と複数の split APK）の場合：

- ファイルピッカーで `base.apk` とすべての split を一度に選択します。
- base だけを選択するとリソースやネイティブライブラリが不足し、アプリが起動できない場合があります。

インポート時には次の項目がチェックされます。

- パッケージ名が有効かどうか。
- 複数回インポートしたときに署名が一致するかどうか。
- `minSdk` が現在のシステムより高いかどうか。
- APK が `REQUIRE_SECURE_ENV` を宣言しているかどうか。

検証に失敗した場合はインポート画面に理由が表示され、インストールは行われません。

## 5. アプリの起動

「スペース設定」→「アプリ管理」に移動し、先ほどインポートしたアプリを見つけます。

- アプリの行の左側で「インスタンス 1」「インスタンス 2」などを選択できます。
- 「启动」（起動）をタップすると、選択中のインスタンスが開きます。
- 「多开」（複製（マルチインスタンス））をタップすると、新しいインスタンスを作成して起動します。

![アプリ管理と複製（マルチインスタンス）](screenshots/app-manager.jpg)

各インスタンスは独立した `files`、`cache`、`code_cache`、`databases`、SharedPreferences 名前空間を持っているため、2 つのインスタンスで同じアプリの 2 つのアカウントに同時にログインできます。

## 6. デスクトップの整理

- アプリのアイコンを長押し：開く、アプリショートカット、最前面へ移動／最後尾へ移動、アプリ情報などのメニューが開きます。フォルダが既にある場合はフォルダに追加することもできます。仮想アプリは全インスタンスデータとともにアンインストールできます。
- 空白部分を長押し：新しいフォルダ、モデル設定、権限レベル。
- 長押ししてドラッグ：アイコンの順序を調整します。別のアプリの上にドラッグし、重なりが小さい場合はフォルダのゴーストが表示されてフォルダが作成され、重なりが 30% 以上になると挿入／移動に変わります。既存のフォルダの上にドラッグすると、そのフォルダに追加されます。
- フォルダ：開く、名前変更、アプリの追加、解散ができます。開いた後にアプリを長押しするとフォルダから移動でき、上方向にドラッグしても移動できます。アプリが 1 つだけになったフォルダは自動的に解散します。
- 壁紙：「スペース設定 → デスクトップ壁紙」。
- デスクトップのレイアウトは自動的に保存され、再起動後も維持されます。

## 7. AI アシスタントを使う（任意）

デスクトップの AI アシスタントをタップします。

- モデルが設定されていない場合は未接続状態と設定ボタンが表示され、設定が完了するまでコマンドやツール呼び出しは実行されません。
- 「スペース設定」→「模型设置」（モデル設定）で Claude 互換または OpenAI 互換のインターフェースを設定すると、より複雑なマルチステップタスクを実行できます。返信はストリーミングテキストで表示され、ツール呼び出しは展開可能なカードとして表示されます。
- アシスタントが制御する仮想アプリはデフォルトでミラーを使用します。`display_mode` で `background` または `visible` を選択でき、`hand_to_user` でログイン、CAPTCHA、支払い、承認などをユーザーに引き継げます。
- 対話が終了すると、アシスタントは自動的にメモリを整理します。成功したマルチステップタスクからはスキルを自動起草できます。事実と好みはそのまま反映され、再利用可能な手順は標準権限ではそのまま反映され、厳格権限では先に対話内で確認されます。自動起草されたスキルはデフォルトで無効になっており、手動で有効にする必要があります。

詳細は [AI アシスタント](assistant.md) を参照してください。

## 8. 仮想アプリのアンインストール

次の 2 つの方法があります。

- デスクトップのアイコンを長押し →「卸载」（アンインストール）。
- 「スペース設定」→「アプリ管理」→ アプリの行にある「アンインストール」。

アンインストールすると、インストール済みの APK、そのアプリのすべてのインスタンスとインスタンスデータが削除され、復元できません。

## 9. データの保存場所

NestSpace のアプリ専用ディレクトリ内に保存されます。

```text
/data/user/0/com.coke.nestspace/files/vspace/
  apps/                     安装的 APK
  data/<package>/<instance>/ 实例数据
```

一般のユーザーがこれらのディレクトリに手動でアクセスする必要はありません。NestSpace 自体をアンインストールすると、すべての仮想アプリとインスタンスデータも一緒に削除されます。
