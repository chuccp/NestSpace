# 應用程式安裝與管理

入口：**「空间设置」（空間設定）→「应用管理」（應用程式管理）**。

![應用程式管理與多開](screenshots/app-manager.jpg)

頁面目前有兩種新增方式：

1. **匯入應用程式**：從宿主 Android 已安裝的應用程式中選擇 APK，安裝到虛擬空間。
2. **匯入 APK**：從檔案選擇器選擇本機 APK，或一次選擇 split APK 的全部檔案。

匯入後都會成為 NestSpace 的虛擬應用程式，擁有獨立執行個體和資料目錄。目前介面不再區分「虛擬應用程式」與「桌面應用程式」，也不會建立系統應用程式捷徑。

## 匯入宿主已安裝的應用程式

1. 點「匯入應用程式」。
2. NestSpace 讀取可匯入的宿主應用程式。
3. 勾選一個或多個應用程式。
4. 點「匯入」。

- 只匯入宿主應用程式的 APK，不複製帳號、私有資料或登入狀態。
- 首次啟動時建立「執行個體 1」。
- 同套件名稱已存在時，會提示將覆蓋現有版本。
- 覆蓋仍會檢查簽章、最低系統版本和容器相容性。
- Gmail 等系統層級應用程式也可以匯入，但能否執行取決於系統服務和 native 程式庫依賴。

## 匯入 APK

1. 點「匯入 APK」。
2. 在系統檔案選擇器選擇 APK。
3. 等待解析、複製和安裝完成。

split 應用程式需要一次選取全部檔案：

```text
base.apk
split_config.arm64_v8a.apk
split_config.xxhdpi.apk
...
```

只選 base 會缺少程式碼、native 程式庫或資源，應用程式可能啟動失敗。

| 檢查 | 失敗時的行為 |
| --- | --- |
| 套件名稱 | 拒絕安裝 |
| 簽章一致性 | 同套件已有不同簽章時傳回 `SIGNATURE_MISMATCH` |
| `minSdk` | 高於目前系統版本時拒絕安裝 |
| `REQUIRE_SECURE_ENV` | 目標要求安全環境時傳回 `SECURE_ENV_REQUIRED` |
| ABI | 安裝可能成功；啟動時缺少相符 native 程式庫則傳回 `ABI_MISMATCH` |

## 虛擬應用程式與執行個體

每個應用程式列會顯示圖示、名稱、套件、版本、執行個體、啟動、多開、卸載，以及可用的 native 程式庫狀態。

- 點執行個體會啟動該執行個體。
- 點「啟動」會使用最近選取的執行個體。
- 點「多開」會建立新的獨立執行個體。

每個執行個體分別擁有 `files`、`cache`、`code_cache`、`databases`、`getDir`、SharedPreferences 和 native 程式庫解壓目錄，彼此不能直接讀取資料。

### 執行個體詳情

點執行個體可進入詳情頁，查看執行個體 ID、建立時間、最近啟動、環境版本、相容設定、最近探測和實際資料目錄。

「清空此執行個體資料」只重設該執行個體；同一應用程式的其他執行個體和已安裝 APK 都會保留。

### 同時執行數量

處理程序池預設自動管理，最多 16 個槽位。記憶體不足時會關閉最久未使用的背景容器，前台容器會保留。可在「空間設定 → 應用程式與容器 → 容器槽位」設定 1–16 的固定上限。

## 卸載

卸載虛擬應用程式會刪除 APK、全部執行個體、執行個體資料、快取、資料庫，以及 NestSpace 命名空間中的 SharedPreferences。此操作無法復原。

外掛和虛擬應用程式使用不同資料邊界。卸載虛擬應用程式不會刪除外掛，刪除外掛也不會刪除虛擬應用程式。

## 常見安裝問題

### `SIGNATURE_MISMATCH`

同套件名稱曾安裝不同簽章的 APK。先卸載舊應用程式，或使用相同簽章重新建置。

### `SECURE_ENV_REQUIRED`

目標要求 NestSpace 無法提供的安全執行環境，因此拒絕安裝。

### `ABI_MISMATCH`

APK 的 native ABI 與裝置或目前執行環境不符。請使用相符的套件；ARM64 實機和 ARM 轉譯模擬器通常應使用 arm64 主程式 APK。

### 啟動後黑屏或閃退

通常是應用程式加固、native SDK、動態載入或依賴衝突造成。先執行「空間設定 → 應用程式與容器 → 容器進階 → 容器自檢」，回報時附上應用程式版本、錯誤和自檢報告。

### 安裝成功但桌面沒有圖示

到「空間設定 → 應用程式管理」確認應用程式仍存在，並直接從列表啟動。桌面配置損壞或重設時可能只隱藏圖示，不會刪除應用程式。
