# 常見問題

先嘗試「空间设置」（空間設定）→「容器自检」（容器自我檢查），它能涵蓋啟動、介面、截圖、獨立處理程序、WebView 和 MCP 等基礎能力，並產生可複製的報告。

## 安裝與啟動

### 匯入 APK 失敗

| 提示 | 原因 | 處理 |
| --- | --- | --- |
| `SIGNATURE_MISMATCH` | 同套件名稱已有不同簽章的安裝記錄 | 先卸載舊應用程式，或使用相同簽章重新打包 |
| `SECURE_ENV_REQUIRED` | 目標宣告了 `REQUIRE_SECURE_ENV` | 目前容器不滿足該要求，無法安裝 |
| `minSdk` 相關錯誤 | 目標的 minSdk 高於目前系統 | 升級系統或換用相容版本 |
| 解析失敗 / 不是有效 APK | 檔案損毀或不是 APK | 重新下載，確認檔案完整 |

### 安裝成功但啟動失敗

- 先看是否傳回 `ABI_MISMATCH`。只含 arm64 原生程式庫的應用程式不能在 x86_64 模擬器執行。
- 目標應用程式可能使用了加固、熱更新或自帶 native SDK，這類應用程式需要逐個調適。
- 開啟「容器自我檢查」，確認容器基礎能力正常。
- 記錄應用程式名稱、版本、錯誤資訊，提交 issue。

### 啟動後黑屏、白屏或閃退

常見原因：

- 目標應用程式相依的原生程式庫沒有載入；
- 目標應用程式偵測到執行環境異常；
- 目標 Activity 使用了尚未虛擬化的系統能力；
- 資源或 split 不完整。

可以嘗試：

1. 確認 split APK 是否全部匯入。
2. 在「运行管理」（執行管理）裡關閉該應用程式的全部處理程序，再重新啟動。
3. 換一個版本或架構的 APK 驗證。
4. 附上「容器自我檢查」報告和錯誤資訊提交 issue。

### 桌面沒有應用程式圖示

- 進入「空間設定」→「應用程式管理」，確認「虚拟应用」（虛擬應用程式）清單裡有該應用程式。
- 如果應用程式仍在清單中，使用清單裡的「启动」（啟動），或修復桌面配置。
- 如果應用程式不在清單中，請從宿主應用程式或 APK 重新匯入。

### 重新啟動後安裝記錄消失

正常情況下安裝記錄會持久化。如果清除過 NestSpace 應用程式資料，安裝記錄和執行個體資料會一起遺失，需要重新匯入。

## 多開與記憶體

### 同時開啟多個應用程式後，先前的應用程式被關閉

這是預期的記憶體管理行為：

- 容器處理程序池預設自動管理最多 16 個槽位。
- 記憶體緊張時優先關閉最久未使用的背景容器；前景容器不會被關閉。
- 可以在「空間設定」→「容器槽位」設定固定上限。
- 在「執行管理」裡可以手動關閉不需要的處理程序，釋放記憶體。

### 執行個體資料會遺失嗎

結束處理程序不會刪除資料。應用程式資料儲存在 `files/vspace/data/<package>/<instance>/`，下次啟動會繼續使用。

### 資料能在執行個體之間共用嗎

不能。每個執行個體的 files、cache、databases、code_cache 和 SharedPreferences 命名空間是獨立的。需要共用資料時，只能透過應用程式自身的帳號同步或匯出功能。

## 背景與無頭執行

### `LAUNCH_BLOCKED`

在沒有開啟 NestSpace 介面時啟動容器，需要懸浮窗權限提供的背景 Activity 啟動豁免：

1. 開啟「空間設定」→「MCP 控制服务」（MCP 控制服務）。
2. 按提示授予「显示在其他应用上层」（顯示在其他應用程式上層）權限。
3. 重新呼叫 `space_launch`。

### 應用程式退到背景後被系統終止

Android 會依記憶體和背景策略回收處理程序。NestSpace 只能保證前景容器不被自己的槽位管理關閉，不能阻止系統回收整個應用程式。需要長期背景執行時，請關閉電池最佳化並允許背景活動。

### 定時任務沒有執行

- 確認任務已啟用。
- 允許 NestSpace 背景執行，並關閉省電模式對鬧鐘的限制。
- 檢查系統是否限制了精確鬧鐘權限。
- 任務會在下次啟動後恢復排程。

## AI 助手

### 助手顯示尚未設定模型

目前版本不再提供離線規則 Agent。送出任務前必須先設定可用模型；設定完成前不會執行指令或工具呼叫。

- 在「空間設定」→「模型设置」（模型設定）確認已儲存可用設定並選取。
- 點「測試連線」確認介面可用。
- 檢查 Base URL、API Key、模型名稱。
- 檢視對話中的錯誤訊息和「Token 統計」。

### 工具呼叫達到上限

預設單輪最多 128 次工具呼叫。複雜任務可以把「最大工具輪次」調高，或者把任務拆成幾步。

### 助手不操作目標應用程式

助手固定在「虚拟空间 1」（虛擬空間 1）。確認應用程式已經安裝並啟動，且沒有被其他執行個體佔用。

### 語音辨識沒有結果

- 授予錄音權限。
- 確認離線語音模型已下載。
- 在「空間設定」→「悬浮球」（懸浮球）中切換語言模型後重試。
- 首次下載失敗時，換一個模型來源再試。

## 瀏覽器

### 頁面打不開或一直空白

- 檢查網路連線。
- 如果啟用了代理，確認代理位址和連接埠正確，或臨時關閉代理。
- 某些網站會攔截 WebView，嘗試用系統瀏覽器開啟相同位址驗證。
- 頁面需要登入或驗證碼時，使用「轉交使用者」模式處理。

### 代理未生效

- 需要 Android 10+ 且 WebView 支援 `PROXY_OVERRIDE`。
- 伺服器位址只填主機名稱或 IP，不要帶 `http://`、連接埠或斜線。
- 不支援需要使用者名稱/密碼的代理。
- 修改後重新開啟瀏覽器分頁。

### 下載失敗

- 確認系統和 NestSpace 有寫入下載目錄的權限。
- 檢查可用儲存空間。
- 部分網站使用 Blob 或受保護連結，WebView 可能無法直接下載。

## MCP

### 連線被拒絕

- 確認服務在「MCP 控制服務」裡顯示執行中。
- USB 模式確認已執行 `adb forward tcp:8765 tcp:8765`。
- 區域網路模式確認同一 Wi-Fi、IP 正確、已授予區域網路權限。

### 401 / 404

- 401：Token 錯誤或沒有帶 `Authorization: Bearer <token>`。
- 404：路徑錯誤或工作階段過期。位址應以 `/mcp` 結尾；閒置 30 分鐘後會回收工作階段，重連即可。

### 電腦能連但手機上沒有變化

- 確認呼叫的是容器工具，並且目標應用程式已經在 `virtual-1` 中啟動。
- 需要背景啟動時檢查懸浮窗權限。
- 檢視 MCP 工具傳回的錯誤資訊。

## 資料與重設

### 資料在哪裡

```text
/data/user/0/com.coke.nestspace/files/vspace/
  apps/                     安裝的 APK
  data/<package>/<instance>/ 執行個體資料
```

### 如何徹底重設

在系統設定裡清除 NestSpace 的應用程式資料，或在系統裡卸載 NestSpace。兩者都會刪除：

- 所有虛擬應用程式和執行個體資料；
- 桌面版面配置和壁紙；
- 模型設定、記憶、技能和定時任務；
- MCP Token。

### 如何只刪除一個應用程式

「空間設定」→「應用程式管理」→ 應用程式列「卸載」。這只會刪除該應用程式及其全部執行個體資料。

## 回報問題時請附上

- 手機型號、Android 版本；
- NestSpace 版本（「空間設定」→「关于」（關於））；
- 目標應用程式名稱和版本；
- 「容器自我檢查」報告；
- 具體操作步驟和錯誤提示。
