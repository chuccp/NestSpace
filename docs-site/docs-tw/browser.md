# 內建瀏覽器

NestSpace 自帶一個以 WebView 為基礎的多分頁瀏覽器，桌面有「浏览器」（瀏覽器）入口。它和 AI 助手共用同一套瀏覽器能力：助手可以在背景開啟分頁、讀取頁面、點擊和下載，使用者也可以隨時接管。

## 開啟瀏覽器

- 桌面「瀏覽器」。
- AI 助手呼叫 `browser_open` 開啟可見瀏覽器（`headless=false`）。
- 助手預設開啟的是**無頭分頁**，可以在可見瀏覽器的分頁列裡看到並接管。

## 分頁

- 支援多分頁，最多同時保留 10 個。
- 分頁列可以切換、關閉和新增分頁。
- 關閉目前分頁會選取相鄰分頁。
- 無頭分頁由助手建立，開啟可見瀏覽器後可以直接點選並接管，頁面狀態不會遺失。
- 所有分頁共用同一個處理程序，但各自有獨立的 WebView。

## 網址列

- 輸入完整 URL 開啟網頁。
- 輸入一般文字會用 Bing 搜尋。
- 支援上一頁、下一頁和重新整理。

## 無頭模式

助手呼叫 `browser_open` 時預設 `headless=true`：

- 頁面在背景載入，不佔用前景；
- 助手可以用 `tab_id` 分別讀取、點擊和導覽多個頁面；
- 需要使用者處理驗證碼或登入時，助手可以呼叫 `browser_hand_to_user` 把頁面切換到可見瀏覽器。

## 下載

- 頁面觸發的下載會寫入系統 **Download** 目錄。
- Android 10+ 透過 MediaStore 儲存，傳回檔案名稱、路徑、大小和 `content://` URI。
- 下載好的 APK 可以直接在「应用管理」（應用程式管理）→「导入 APK」（匯入 APK）裡選擇，或交給 `space_install_apk`。
- 助手使用 `browser_download` 啟動 URL 下載，會立即回傳 `download_id` 和 `task_id`。
- 使用 `task_wait` 等待到 `terminal=true`。只有 `state=succeeded` 才算成功，逾時不會取消下載。
- 需要位元組數、百分比或檔案資訊時，使用 `browser_download_status`。
- 每個助手工作階段只保留一個目前下載。啟動新下載會取消該工作階段先前的下載，使用者和其他工作階段的下載仍可繼續。

## 上傳

- 頁面上傳按鈕會開啟系統檔案選擇器。
- 助手可以呼叫 `browser_upload`，用本機路徑或 `content://` URI 完成目前等待的檔案選擇。
- 也可以由使用者手動選擇檔案。

## 驗證碼、登入和反爬蟲

頁面出現驗證碼、人機驗證、登入牆或反爬蟲攔截時：

- 助手會偵測到 `needs_user` / `user_reason` / `challenge` 提示。
- 呼叫 `browser_hand_to_user` 把分頁切換到可見瀏覽器，交給使用者處理。
- 使用者點「完成」後，助手會收到目前 URL、標題、正文和是否仍被封鎖。

助手不會嘗試繞過驗證碼或登入限制。

## 代理

入口：

- 瀏覽器右上角齒輪。
- 「空间设置」（空間設定）→「浏览器代理」（瀏覽器代理）。

設定項目：

- 啟用/關閉；
- 類型（HTTP / SOCKS）；
- 伺服器位址（只填主機名稱或 IP，不要帶協定、連接埠或斜線）；
- 連接埠；
- 略過代理的位址（逗號分隔，選用）。

說明：

- 所有分頁和瀏覽器下載共用同一個代理。
- 需要 Android 10+ 且 WebView 支援 `PROXY_OVERRIDE`。
- 目前不支援需要使用者名稱/密碼驗證的代理。
- 重新啟動應用程式後設定會自動恢復。
- 也可以使用 MCP 工具 `nestspace_browser_proxy` 設定。

## 限制

- 頁面在 WebView 中執行，不等同於系統瀏覽器；某些網站會偵測 WebView 或限制功能。
- 登入狀態取決於 WebView 的 Cookie，清除 NestSpace 資料會一併清除。
- 反爬蟲、驗證碼和登入必須由使用者處理，助手只負責轉交。
- 代理是明文轉送，不負責 TLS 終止。
