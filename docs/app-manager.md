# 应用安装与管理

入口：**空间设置 → 应用管理**。

![应用管理与多开](screenshots/app-manager.jpg)

当前页面只有两种添加入口：

1. **导入应用**：从宿主 Android 已安装的应用中选择 APK，安装到虚拟空间。
2. **导入 APK**：从文件选择器选择本地 APK 或 split APK。

导入完成后，应用都会成为 NestSpace 的虚拟应用，拥有独立实例和数据目录。这里不再区分“虚拟应用”和“桌面应用”，也不会创建系统应用快捷方式。

## 导入宿主已安装的应用

1. 点「导入应用」。
2. NestSpace 读取宿主上可导入的应用。
3. 勾选一个或多个应用。
4. 点「导入」。

说明：

- 导入的是宿主应用的 APK，不会复制宿主应用的账号、私有数据或登录状态。
- 应用会安装到虚拟空间，首次启动时创建「实例 1」。
- 如果同一包名已经导入，列表会提示“已导入，将覆盖”。
- 覆盖仍会检查签名、最低系统版本和容器兼容性。
- Gmail 等系统级应用也可以导入，但能否运行取决于它的系统服务和原生库依赖。

## 导入 APK

1. 点「导入 APK」。
2. 在系统文件选择器里选择 APK。
3. 等待解析、复制和安装完成。

普通应用选择一个 APK。split 应用需要一次选中所有文件：

```text
base.apk
split_config.arm64_v8a.apk
split_config.xxhdpi.apk
...
```

只选 base 会缺少代码、native 库或资源，应用可能在启动时失败。

导入时会检查：

| 检查 | 失败时的行为 |
| --- | --- |
| 包名 | 拒绝安装 |
| 签名一致性 | 同包名已有不同签名时返回 `SIGNATURE_MISMATCH` |
| `minSdk` | 高于当前系统版本时拒绝安装 |
| `REQUIRE_SECURE_ENV` | 目标要求安全环境时返回 `SECURE_ENV_REQUIRED` |
| ABI | 安装会成功；启动时缺少匹配 native 库则返回 `ABI_MISMATCH` |

## 应用列表

每个已安装应用显示：

- 图标、名称、包名和版本；
- 当前已有实例；
- 「启动」；
- 「多开」；
- 「卸载」；
- native 库标记（如果存在）。

### 启动

点某个实例会启动该实例；点主「启动」按钮会使用最近选择的实例。

### 实例详情

点实例可以进入独立详情页，查看实例 ID、创建时间、最近启动、环境版本、兼容配置、
最近探测和实际数据目录。每个实例拥有独立运行环境；清空某个实例的数据不会影响同一
应用的其他实例，也不会删除已安装 APK。

### 多开

点「多开」会创建新实例并启动。每个实例拥有独立的：

- `files`
- `cache`
- `code_cache`
- `databases`
- `getDir`
- SharedPreferences 命名空间
- native 库提取目录

因此同一个 App 可以同时登录两个账号，实例之间不能直接读取对方数据。

### 同时运行数量

容器进程池默认自动管理，最多 16 个槽位。内存紧张时会关闭最久未使用的后台容器，前台容器不会被关闭。

固定上限入口：

**空间设置 → 应用与容器 → 容器槽位**

可以设置为 1–16 个。降低上限会立即结束超出范围的容器进程，但不会删除应用数据。

## 卸载

点应用行里的「卸载」，确认后会删除：

- 已安装的 APK；
- 全部实例；
- 实例数据、缓存和数据库；
- 该应用在 NestSpace 命名空间下的 SharedPreferences。

此操作不可恢复。

插件和虚拟应用使用不同的数据边界。虚拟应用卸载不会删除插件，插件删除也不会删除
虚拟应用。插件包、私有存储、缓存、SQLite、设置和密钥由插件中心单独管理。

## 常见安装问题

### `SIGNATURE_MISMATCH`

同一个包名之前安装过不同签名的 APK。先卸载旧应用再安装，或使用相同签名重新打包。

### `SECURE_ENV_REQUIRED`

目标应用声明了 `REQUIRE_SECURE_ENV`。NestSpace 不是它要求的安全环境，目前会拒绝安装。

### `ABI_MISMATCH`

APK 的 native 库与当前设备或其他实例架构不匹配。ARM64 真机和带 ARM 转译的 MuMu 建议使用 arm64 主程序包。

### 启动后黑屏或闪退

通常是应用兼容性问题，例如加固、native SDK、动态加载或依赖冲突。可以先运行：

**空间设置 → 应用与容器 → 容器高级 → 容器自检**

反馈时请附应用名称、版本、错误信息和自检报告。

### 导入成功但桌面没有图标

先进入「空间设置 → 应用管理」确认应用是否存在，并从应用列表直接启动。桌面布局损坏或被清除时，可以从应用列表重新打开应用。
