# 常见问题

先尝试「空间设置 → 应用与容器 → 容器高级 → 容器自检」，它能覆盖启动、界面、截图、独立进程、WebView 和 MCP 等基础能力，并生成可复制的报告。

## 安装与启动

### 导入 APK 失败

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| `SIGNATURE_MISMATCH` | 同包名已有不同签名的安装记录 | 先卸载旧应用，或使用相同签名重新打包 |
| `SECURE_ENV_REQUIRED` | 目标声明了 `REQUIRE_SECURE_ENV` | 当前容器不满足该要求，无法安装 |
| `minSdk` 相关错误 | 目标的 minSdk 高于当前系统 | 升级系统或换用兼容版本 |
| 解析失败 / 不是有效 APK | 文件损坏或不是 APK | 重新下载，确认文件完整 |

### 安装成功但启动失败

- 先看是否返回 `ABI_MISMATCH`。只含 arm64 原生库的应用不能在 x86_64 模拟器运行。
- 目标应用可能使用了加固、热更新或自带 native SDK，这类应用需要逐个适配。
- 打开「容器自检」，确认容器基础能力正常。
- 记录应用名称、版本、错误信息，提交 issue。

### 启动后黑屏、白屏或闪退

常见原因：

- 目标应用依赖的 native 库没有加载；
- 目标应用检测到运行环境异常；
- 目标 Activity 使用了尚未虚拟化的系统能力；
- 资源或 split 不完整。

可以尝试：

1. 确认 split APK 是否全部导入。
2. 在「运行管理」里关闭该应用的全部进程，再重新启动。
3. 换一个版本或架构的 APK 验证。
4. 附上「容器自检」报告和错误信息提交 issue。

### 桌面没有应用图标

- 进入「空间设置 → 应用管理」，确认「虚拟应用」列表里有该应用。
- 如果桌面图标异常，直接从应用列表点「启动」。
- 从宿主导入应用时，NestSpace 会安装独立虚拟副本，不会创建系统应用快捷方式。

### 重启后安装记录消失

正常情况下安装记录会持久化。如果清除过 NestSpace 应用数据，安装记录和实例数据会一起丢失，需要重新导入。

## 多开与内存

### 同时打开多个应用后，之前的应用被关闭

这是预期的内存管理行为：

- 容器进程池默认自动管理最多 16 个槽位。
- 内存紧张时优先关闭最久未使用的后台容器；前台容器不会被关闭。
- 可以在「空间设置 → 应用与容器 → 容器槽位」设置固定上限。
- 在「运行管理」里可以手动关闭不需要的进程，释放内存。

### 实例数据会丢吗

结束进程不会删除数据。应用数据保存在 `files/vspace/data/<package>/<instance>/`，下次启动会继续使用。

### 数据能在实例之间共享吗

不能。每个实例的 files、cache、databases、code_cache 和 SharedPreferences 命名空间是独立的。需要共享数据时，只能通过应用自身的账号同步或导出功能。

## 后台与无头运行

### `LAUNCH_BLOCKED`

在没有打开 NestSpace 界面时启动容器，需要悬浮窗权限提供的后台 Activity 启动豁免：

1. 打开「空间设置 → MCP 控制服务」。
2. 按提示授予「显示在其他应用上层」权限。
3. 重新调用 `space_launch`。

### 应用退到后台后被系统杀死

Android 会按内存和后台策略回收进程。NestSpace 只能保证前台容器不被自己的槽位管理关闭，不能阻止系统回收整个应用。需要长期后台运行时，请关闭电池优化并允许后台活动。

### 定时任务没有执行

- 确认任务已启用。
- 允许 NestSpace 后台运行，并关闭省电模式对闹钟的限制。
- 检查系统是否限制了精确闹钟权限。
- 任务会在下次启动后恢复调度。

## AI 助手

### AI 助手提示未配置模型

当前版本不再提供离线规则 Agent。请先在「空间设置 → 模型设置」保存一个可用模型；未配置时助手不会执行命令或工具调用。

- 「空间设置 → 模型设置」确认已保存配置并选中。
- 点「测试连接」确认接口可用。
- 检查 Base URL、API Key、模型名称。
- Claude 兼容接口缺少版本路径时会自动补 `/v1/messages`。
- 连接成功和失败结果以 Toast 显示，不再出现在页面顶部。
- 查看对话中的错误消息和「Token 统计」。

### 工具调用达到上限

默认单轮最多 128 次工具调用。复杂任务可以把「最大工具轮次」调高，或者把任务拆成几步。

### 助手不操作目标应用

助手固定在「虚拟空间 1」。确认应用已经安装并启动，且没有被其他实例占用。

### 助手操作应用时出现全屏或系统 PiP

- 本地助手默认使用镜像小窗，只有显式选择 `visible` 或调用 `hand_to_user` 时才应进入前台。
- 如果任务应在后台运行，确认调用方传入 `display_mode=background`。
- AI 托管任务不会额外进入系统 PiP；如果仍出现，请记录对话内容、任务 ID 和工具调用。

### 语音识别没有结果

- 授予录音权限。
- 确认离线语音模型已下载。
- 在「空间设置 → 悬浮球」中切换语言模型后重试。
- 首次下载失败时，换一个模型来源再试。

### 中文语音出现大量空格

当前版本会自动去掉中文字符之间的识别空格，例如
`打 开 应 用` 会整理为 `打开应用`。如果仍出现异常，请记录完整识别文本和语音模型语言。

## 浏览器

### 页面打不开或一直空白

- 检查网络连接。
- 如果启用了代理，确认代理地址和端口正确，或临时关闭代理。
- 某些站点会拦截 WebView；可更换站点版本或通过浏览器设置检查代理，不要用系统浏览器绕过 AI 操作流程。
- 页面需要登录或验证码时，使用「交给用户」模式处理。

网页弹窗、`target=_blank`、`window.open`、`intent://` 网页回退地址和下载页均应由自带浏览器接管。如果系统浏览器仍被打开，请记录原始页面 URL 和点击元素后提交 issue。

### 代理不生效

- 需要 Android 10+ 且 WebView 支持 `PROXY_OVERRIDE`。
- 服务器地址只填主机名或 IP，不要带 `http://`、端口或斜杠。
- 不支持需要用户名/密码的代理。
- 修改后重新打开浏览器标签。

### 下载失败

- Android 10+ 通过 MediaStore 保存到系统 Download 目录，不需要额外存储权限。
- 检查可用存储空间。
- 部分站点使用 Blob 或受保护链接，WebView 可能无法直接下载。

## MCP

### 连接被拒绝

- 确认服务在「MCP 控制服务」里显示运行中。
- USB 模式确认已执行 `adb forward tcp:8765 tcp:8765`。
- 局域网模式确认同一 Wi-Fi、IP 正确、已授予局域网权限。

### 401 / 404

- 401：Token 错误或没有带 `Authorization: Bearer <token>`。
- 404：路径错误或会话过期。地址应以 `/mcp` 结尾；空闲 30 分钟后会回收会话，重连即可。

### 电脑能连但手机上没有变化

- 确认调用的是容器工具，并且目标应用已经在 `virtual-1` 中启动。
- 需要后台启动时检查悬浮窗权限。
- 查看 MCP 工具返回的错误信息。

## 插件中心

### 源码插件没有出现

- 确认插件位于 `dev-plugins/<name>` 或 `example-plugin/plugin`；
- 确认目录中包含 `build.gradle.kts`、`src/main/plugin-assets/manifest.json` 和入口类；
- 检查 Manifest `id`、`entry_class`、Gradle namespace 和 Java 包名；
- 重新运行 `:app:assembleDebug`，不要只重新打开 Activity；
- 在 Logcat 中检查 `PluginSourceLoader`。

源码插件会与第三方插件显示在同一网格，图标左下角带有“源码”角标。它不会单独占一栏。

### 看不到系统插件

系统内置插件当前不显示在插件中心，仍在宿主内部按设置运行。插件中心只显示可管理的
源码插件、第三方插件和当前进程已加载但不属于内置模块的插件。

### 长按菜单不能删除某些插件

源码插件随 Debug APK 编译，系统内置能力属于宿主，均不能从插件中心删除。只有第三方
`.nest` 支持删除。源码插件可以通过设置、重命名、分享和导出来管理。

### 插件设置页打不开或显示错误

- 确认 Manifest 声明了 `settings`；
- 确认 Manifest 声明 `settings`，且 `contributes.settings` 指向可解析的 Schema；
- 如果是 Schema 回退模式，检查 `contributions.settings` JSON；
- 查看 `AndroidRuntime`，确认自定义 View 没有在非 UI 线程创建或访问已关闭的 Context。

### 分享或导出失败

- 第三方插件安装目录必须包含 `manifest.json` 和 `classes.dex`；
- 源码插件需要重新构建 Debug APK，以生成自动分享资产；
- 检查系统文件选择器是否有写入权限和可用空间；
- 安装包最大 32 MB，插件资源不应把大型模型或视频打入包内。

### 删除插件后的行为

删除第三方插件会清理插件包、私有文件、缓存、SQLite、设置和密钥密文。当前已经启动的
其他容器槽位可能会继续持有旧 Hook，直到对应进程重启。

## 数据与重置

### 数据在哪里

```text
/data/user/0/com.coke.nestspace/files/vspace/
  apps/                     安装的 APK
  data/<package>/<instance>/ 实例数据
```

### 如何彻底重置

在系统设置里清除 NestSpace 的应用数据，或在系统里卸载 NestSpace。两者都会删除：

- 所有虚拟应用和实例数据；
- 桌面布局和壁纸；
- 模型配置、记忆、技能和定时任务；
- MCP Token。

### 如何只删一个应用

「空间设置 → 应用管理」→ 应用行「卸载」。这只删除该应用及其全部实例数据。

## 反馈问题时请附上

- 手机型号、Android 版本；
- NestSpace 版本（「空间设置 → 关于」）；
- 目标应用名称和版本；
- 「容器自检」报告；
- 具体操作步骤和错误提示。
