# NestSpace 容器悬浮工具栏智能读屏设计

- 状态：设计评审
- 版本：1.0
- 日期：2026-11-24
- 适用范围：容器内虚拟应用；第一版不覆盖宿主系统应用

## 1 结论

在容器悬浮工具栏中增加第三个“读屏”入口。点击后由独立的读屏 Agent 观察当前页面、解释屏幕信息、给出候选处理方式，并在执行前让用户确认。

读屏 Agent 可以创建 Worker 处理耗时操作，但不能直接点击、输入或导航。系统不能把意图推断直接当成用户授权。意图明确时可以提供推荐项；意图不明确时必须询问。点击、导航、输入、发送、安装和支付等动作必须经过确认，验证码、登录和支付交给用户处理。

第一版优先做按需读屏，不做持续监听，也不依赖全局无障碍服务。

## 2 设计目标

1. 用户点一下就能知道当前页面是什么、主要内容有哪些、可以执行哪些操作。
2. 系统可以从页面和最近会话中推断意图，但不替用户做决定。
3. 用户可以用语音或按钮选择处理方式，并随时改变主意。
4. 风险动作有明确边界，不因模型判断错误而误点击或误导航。
5. 保持现有贴边悬浮工具栏的交互，不引入新的常驻窗口。

第一版不做以下能力：

- 不在用户没有开启读屏时持续观察屏幕。
- 不根据模糊截图猜测按钮功能后直接执行。
- 不绕过验证码、登录、权限确认或支付流程。
- 不把截图、完整节点树和敏感字段长期保存。

## 3 工具栏

工具栏保持现有行为：

- 贴边时只露出一小部分。
- 用户向内拖动后完整显示。
- 无操作十秒后自动缩回。
- 只允许沿当前边缘上下移动，不允许自由拖到屏幕中间。

展开后显示三个等宽操作项，图标在上，文字在下：

| 工具 | 图标 | 文字 | 附加状态 |
| --- | --- | --- | --- |
| 语音 | 麦克风 | 语音 | 无 |
| 任务 | 任务清单 | 任务 | 右上角显示执行中任务数字徽章 |
| 读屏 | 页面扫描框 | 读屏 | 读屏中可显示绿色状态点 |

读屏入口只读取和分析当前页面，不自动点击、输入、滚动或导航。

## 4 用户流程

```text
用户点击读屏
    ↓
创建独立读屏 Agent
    ↓
读取当前容器页面
    ↓
整理 ScreenDocument
    ↓
判断页面类型和候选意图
    ↓
明确：推荐一个处理方式
不明确：询问用户要做什么
    ↓
用户确认或改选
    ↓
执行只读处理
    ↓
需要改变页面状态时再次确认
    ↓
读屏 Agent 可创建 Worker
    ↓
在悬浮面板输出结果并允许继续追问
```

执行结束后提供以下后续操作：

- 朗读结果
- 提炼重点
- 展开全文
- 返回原文
- 换一种处理方式
- 撤销可逆操作

## 5 当前屏幕理解

原始 View 树通常包含大量嵌套和无意义节点。读屏层应先转换为语义结构，再交给语言模型或规则逻辑。

| 字段 | 内容 | 用途 |
| --- | --- | --- |
| `page_type` | 新闻、商品、聊天、表单、设置、视频、未知 | 选择解释和阅读策略 |
| `title` | 页面主标题 | 生成摘要和朗读开头 |
| `summary` | 页面级摘要 | 回答“这是什么页面” |
| `blocks` | 标题、正文、列表、表格、图片说明 | 建立自然阅读顺序 |
| `actions` | 按钮、输入框、链接、开关 | 建立编号操作项 |
| `sensitive` | 登录、验证码、支付、权限提示 | 阻止自动操作 |
| `confidence` | 页面结构和意图置信度 | 决定是否需要询问 |

语义整理规则：

1. 优先保留有文本、内容描述、可编辑、可滚动或可点击属性的节点。
2. 合并重复文本和父子节点中的重复语义。
3. 过滤不可见、禁用和无意义容器。
4. 按照从上到下、从左到右、内容分组的顺序建立阅读流。
5. 为操作项分配稳定编号，编号与屏幕高亮保持一致。
6. 密码、验证码、银行卡、身份证和支付字段在进入模型前遮蔽。

## 6 意图判断

候选意图来自四类信息：

- 当前页面类型和主要内容。
- 当前可见操作项。
- 用户最近一次明确输入。
- 正在运行的任务和相关会话上下文。

应用名称只能作为弱信号。用户打开了新闻应用，不代表用户一定想摘要；用户打开购物页面，也不代表用户准备购买。

### 意图分类

一次读屏可以有多个候选意图，但必须选出一个主意图。主意图决定接下来需要什么输出、目标节点和确认等级。

| 意图组 | 具体意图 | 典型表达 |
| --- | --- | --- |
| 理解页面 | 摘要、解释页面用途、解释术语 | “这页讲了什么”“这个词是什么意思” |
| 页面问答 | 根据当前屏幕回答问题 | “有没有提到退款”“活动什么时候结束” |
| 提取整理 | 提取价格、地址、时间、表格、联系人、代码 | “把参数整理成表格”“地址发我” |
| 比较决策 | 比较页面内多个选项或方案 | “这两个套餐哪个更划算” |
| 内容转换 | 翻译、简化、改写、生成清单 | “翻译第二条”“改成待办列表” |
| 查找定位 | 在当前页面中寻找文本、区块或操作 | “找到客服按钮”“跳到评价部分” |
| 导航 | 打开详情、下一页、地图或拨号 | “打开第三条”“带我去这个地址” |
| 页面操作 | 点击、输入、选择、提交 | “填我的手机号”“点第二个按钮” |
| 保存与提醒 | 保存到笔记、加入日历、设置提醒 | “保存这篇文章”“明天提醒我” |
| 持续监控 | 观察价格、库存、更新或状态变化 | “降价后告诉我”“等加载完提醒我” |
| 辅助阅读 | 朗读、逐段读、高亮、只看操作项 | “读慢一点”“只读按钮” |
| 澄清 | 指代不明、目标不明或风险不一致 | “你说的‘这个’是哪一个” |

复合意图必须拆成有序步骤。例如“翻译第二条并收藏”包含内容转换和页面操作两个意图，前者只读，后者改变状态，不能合并成一个无确认的点击动作。

意图结果不能只有一个标签，应同时保留目标、期望输出、风险和执行条件：

```json
{
  "category": "navigate",
  "goal": "打开当前页面中的第二条详情",
  "target_node_id": "v42",
  "target_label": "第二条：城市公共空间更新",
  "expected_result": "进入新闻详情页",
  "confidence": 0.74,
  "risk": "medium",
  "requires_confirmation": true,
  "persistence": "none",
  "alternatives": ["解读第二条", "翻译第二条"]
}
```

当两个候选意图的置信度差小于 0.12，或两者的风险和副作用明显不同，系统必须询问用户，不能选择置信度略高但风险更大的那个。

| 置信度 | 界面行为 | 执行规则 |
| --- | --- | --- |
| 高 | 突出一个推荐处理方式，同时保留其他选项 | 用户确认后执行 |
| 中 | 显示两到四个候选处理方式 | 用户选择并确认后执行 |
| 低 | 不猜测，直接询问用户要做什么 | 等待用户说明 |

第一版建议：

- 高置信度：大于或等于 0.80。
- 中置信度：0.55 至 0.80。
- 低置信度：小于 0.55。

阈值必须通过真实会话评测调整，重点看误执行率和用户纠错次数，不能只依赖模型自报分数。

## 7 可选处理方式

| 处理方式 | 典型结果 | 确认要求 |
| --- | --- | --- |
| 解读这页 | 摘要、关键结论、页面用途 | 推断得到时先确认；用户明确要求时可直接执行 |
| 回答页面问题 | 根据当前屏幕给出可追溯回答 | 只读查询，可直接执行 |
| 提取和整理 | 表格、参数、地址、时间、联系人 | 预览结果，不修改原页面 |
| 比较选项 | 对比差异、给出适用条件 | 只读查询，不替用户做最终决定 |
| 翻译内容 | 原文与译文对照 | 推断得到时先确认；不改变原页面 |
| 查找信息 | 回答价格、时间、地址、联系人等 | 只读查询，可直接执行 |
| 查找定位 | 在当前页面中定位文本或操作项 | 只高亮或滚动，不点击 |
| 继续导航 | 打开链接、详情、下一页或相关条目 | 必须确认目标和动作 |
| 操作页面 | 点击、输入、切换或选择 | 必须确认，风险动作二次确认 |
| 保存与提醒 | 笔记、书签、日历、定时提醒 | 预览保存内容和去向 |
| 持续监控 | 价格、库存、页面更新、任务完成 | 明确监控范围、频率和结束条件 |
| 辅助阅读 | 朗读、逐段读、高亮、操作项模式 | 只改变读屏呈现，不修改页面 |
| 其他处理 | 用户自由输入或语音补充要求 | 先复述理解，再决定执行 |

界面使用“你可能想”而不是“你一定是想”。低置信度显示“意图不明确”提示。主按钮文字随选择变化，例如：

- 确认解读当前页面
- 确认翻译当前内容
- 确认打开第 2 条
- 确认输入并提交

## 8 确认与风险边界

| 操作类别 | 示例 | 确认方式 |
| --- | --- | --- |
| 只读解释 | 摘要、解释页面、查找信息 | 推断时预览并确认；明确指令可直接执行 |
| 内容改写 | 翻译、改写、整理要点 | 确认处理方式后执行 |
| 导航 | 打开链接、下一页、详情 | 确认目标文字或编号 |
| 输入和提交 | 输入文字、发送消息、提交表单 | 确认内容和目标 |
| 安装和删除 | 安装、卸载、删除文件 | 高风险确认 |
| 支付和身份 | 支付、转账、验证码、登录 | 不代理执行，交给用户 |

确认页必须提供取消按钮。用户选择“其他处理”时，不要求从固定选项中强行选择。

## 9 读屏与朗读

开始读屏后，页面保持原位。可读区块按自然顺序编号，当前区块使用细描边高亮，底部或悬浮控制条显示朗读状态。

第一版控制项：

- 暂停和继续
- 停止
- 上一段和下一段
- 摘要和全文切换
- 操作项模式

朗读规则：

1. 默认朗读摘要，用户要求时朗读全文。
2. 跳过装饰性图片、不可见节点和重复导航。
3. 保留价格、日期、单位、百分比和比较对象。
4. 表格按行列标题和单元格内容朗读，不能只读数字。
5. 长页面分段读取，滚动后去重，并保存阅读位置。
6. 按钮朗读同时说明风险，例如“发送”“立即购买”“卸载”。

用户可以直接说：

- “继续”
- “第二条是什么”
- “点第一个按钮”
- “翻译这一段”
- “换一种方式”
- “停下来”

## 10 隐私和安全

1. 默认只读取当前活跃容器，不跨容器扫描。
2. 默认不使用截图，只有节点不足或视觉内容无法表达时才按需截图。
3. 截图和完整节点树不进入长期历史。
4. 敏感字段在提交模型前遮蔽。
5. 读屏期间显示明确状态，用户可随时停止。
6. 不保存原始屏幕内容作为训练数据。
7. 用户保存摘要时，只保存最终文本，不保存截图和节点树。

## 11 独立读屏 Agent

读屏是独立 Agent。它拥有自己的任务身份和执行循环，负责观察页面、整理语义、解释内容、推断意图和形成候选操作。它不能直接执行页面动作，但可以在用户明确确认后创建普通 Worker。

```text
主 Agent
  └─ spawn_screen_reader
       ↓
独立读屏 Agent
  ├─ screen_read：采集并生成结构化屏幕文档
  ├─ screen_highlight：标记当前页面位置
  ├─ screen_query：回答当前页面问题
  ├─ screen_translate：生成双语结果
  ├─ screen_explain：解释页面或指定区块
  └─ spawn_agent：用户确认后创建普通 Worker
```

| 模块 | 职责 | 现有基础 |
| --- | --- | --- |
| 页面采集 | 获取节点和必要截图 | `ContainerUiController`、`ContainerPreviewCapture` |
| 语义整理 | 去重、排序、分类、编号和敏感遮蔽 | 新增 `ScreenDocument` |
| 意图判断 | 生成候选意图、目标和置信度 | 独立读屏 Agent |
| 确认界面 | 显示候选方式、解读结果和动态确认按钮 | 新增半透明悬浮面板 |
| 执行路由 | 调用现有 `ui_*`、`browser_*` | `ToolRegistry` |
| 输出 | 朗读、翻译、摘要和屏幕高亮 | `AssistantSpeech`、读取控制层 |

读屏 Agent 可以使用：

- `screen_read`：读取当前页面并返回结构化屏幕文档。
- `screen_explain`：解释整个页面或指定编号。
- `screen_translate`：生成双语结果，不修改原页面。
- `screen_follow`：处理“继续”“第二条”“换一种方式”等会话指令。
- `spawn_agent`：用户确认后创建 Worker 执行耗时页面操作。

读屏 Agent 不能直接使用 `ui_tap`、`ui_set_text`、提交表单或其他页面变更工具。页面节点整理由确定性的 `ScreenDocumentBuilder` 完成。只有节点无法表达视觉内容时，才在读屏 Agent 的同一轮请求中附带截图。

读屏 Agent 获得的是紧凑的 `ScreenDocument`，包括页面摘要、带编号的区块和操作项、候选意图及风险等级。原始节点树、截图和中间处理结果留在容器上下文，不重复进入对话历史。

页面未变化时复用 `snapshot_id`。点击、导航、弹窗、滚动刷新或页面内容版本变化后，旧快照失效。读屏工具只能观察和解释，真正改变页面状态的动作继续复用现有 `ui_tap`、`ui_set_text` 和风险确认，不增加绕过确认的新入口。

读屏结果使用半透明悬浮面板覆盖在当前容器页面上。读屏失败、澄清、候选方式和执行结果都在同一面板显示，不切换到主助手页面或语音页面。

## 12 异常处理

| 场景 | 处理方式 |
| --- | --- |
| 页面正在加载 | 等待页面稳定后再判断 |
| 节点树为空 | 提示需要截图识别，不编造文字 |
| 页面过长 | 分段整理，只保留当前段和语义索引 |
| 重复节点 | 按文本、边界和层级去重 |
| 弹窗遮挡 | 优先处理弹窗，暂停原页面操作 |
| 登录或验证码 | 停止自动执行，交给用户 |
| 模型不可用 | 保留基础节点朗读和原文高亮 |
| 用户改变主意 | 支持取消、返回原文、撤销和重新选择 |

## 13 第一版验收标准

1. 工具栏增加读屏入口，且不破坏语音和任务入口。
2. 能识别普通 Android View 页面并生成结构化摘要。
3. 节点不足时可按需截图，不默认每次截图。
4. 支持解读、翻译、查找和操作项浏览。
5. 支持编号高亮、暂停、继续、停止和返回原文。
6. 低置信度必须询问用户。
7. 导航、点击、输入和提交必须确认。
8. 验证码、登录和支付交给用户。
9. 敏感字段在进入模型前遮蔽。
10. 用户切换意图后，原任务能够停止或撤销。
11. 点击读屏会创建独立读屏 Agent，不跳离当前容器页面。
12. 读屏 Agent 可以创建 Worker，但不能直接点击、输入或导航。
13. 页面未变化时复用同一份快照，后续追问不重复采集和截图。

## 14 验收用例

| 用例 | 预期结果 |
| --- | --- |
| 新闻页点击读屏 | 识别标题、正文和主要操作，提供摘要和继续朗读 |
| 商品页意图不明确 | 展示查看价格、解读参数、继续浏览等候选，不自动购买 |
| 页面只有图片 | 提示需要视觉识别，获取截图后解释，不编造文字 |
| 用户说点第二个按钮 | 先确认编号对应文本和动作风险，再执行 |
| 出现验证码 | 立即停止自动执行，提示用户接管 |
| 用户要求翻译 | 停止当前朗读，预览翻译方式，确认后显示双语结果 |
| 用户说换一种方式 | 保留当前页面上下文，重新展示候选处理方式 |

## 15 后续能力

- 用户开启后监听页面变化，只朗读新增正文和重要状态。
- 新闻、购物、聊天和表单采用不同的页面阅读模板。
- 表格、图表和图片的视觉理解。
- 全局 `AccessibilityService` 与容器外页面读屏。
- 个人阅读偏好、语速、摘要长度和术语翻译记忆。
